我越来越觉得，字节系在 AI 时代有点可怕了

故事是这样的。

这两天我又打开了一下扣子桌面端。

本来只是想看一眼，看看现在更新到了什么程度。没有特定目的，就是那种很普通的，睡前刷到一个东西，突然手痒，想进去摸一下。

结果打开以后，我有点愣住了。

不是因为它某一个功能特别炸。

而是因为它里面那一整套东西，突然让我意识到一个问题。

字节在大模型时代，好像不是在堆一个个孤立的产品。

它像是在试图把很多 AI 能发生的工作场景，都塞进同一张网里。

扣子，扣子桌面端，扣子编程，Agent World，飞书，飞书 CLI，OpenClaw 插件，Trae，Trae Work，火山引擎，豆包，Seedance 2.0，即梦，抖音小程序，小程序生态。

这些名字单独看，可能都只是一个产品。

但如果你把它们放到一起看，就会发现，这里面有点吓人。

它不是一个聊天框。

它也不是一个编程助手。

它更像是一个正在长出来的，面向普通办公人群和开发者的 AI 工作层。

![扣子编程首页](/images/posts/2026-06-19-bytedance-ai-work-network/image-01-coze-programming.png)

这也是我最近越来越看好字节系的原因。

说真的，一年前我根本想不到这个局面会变成这样。

那个时候大家聊 AI 产品，很多人的第一反应还是海外那一套。写代码就 Cursor，Agent 就 Claude Code，命令行就 Codex，做工作流就各种 MCP，做内容就一堆海外产品。

当然，它们确实强。

这个我没什么好否认的。

但对很多国内用户来说，另一个现实也很刺耳。

你不是天天折腾代理的程序员。

你不是每天都在 GitHub 上追 issue 的重度玩家。

你可能只是一个白领，一个产品经理，一个运营，一个普通开发者，一个每天被文档、表格、会议、需求、代码、素材搞得头大的打工人。

你听说 Claude Code 很强，Codex 很强，Cursor 很强。

然后呢？

下载安装到第一步就开始懵。

账号，网络，账单，模型，额度，API Key，终端，配置文件。

还没开始让 AI 干活，你自己先干了一晚上活。

我非常理解这种感觉。

因为很多东西不是不好，而是离国内普通用户的工作环境太远了。

你每天用的是飞书，是微信，是抖音，是小程序，是国内云服务，是中文文档，是国内支付，是中文协作空间。

如果一个 AI 产品再强，但它每次都要你把工作从自己的环境里搬出去，再搬回来，中间还要忍受各种奇怪的使用成本，那它对普通人来说，就很难真正变成日常工具。

所以我现在看字节系，最感兴趣的不是它做了一个多强的单点。

而是它正在做一件更接地气的事。

把 AI 放回中国用户本来就在用的工作场景里。

这事儿，挺重要的。

我最早用 Trae 的时候，心里其实很简单。

我就是拿它对标 Cursor。

那时候很多人都在讨论 AI 编程，Cursor 在海外开发者圈子里已经很火了，国内自然也会有人问，国产有没有类似的东西。

Trae 一开始给我的感觉，是一个挺清晰的 AI IDE。

写代码，补代码，读项目，改逻辑，生成文档，帮你理解工程。

这些都在预期内。

但后面 Agent 工具开始一波一波往外冒的时候，Trae 很快做出了 Solo 模式。现在这条线变成了 Trae Work。

我当时的感觉是，字节这家公司在 AI 产品上的反应速度，真的有点激进。

激进这个词，我这里不是贬义。

很多大公司做 AI，会有一种大象转身的迟缓感。

内部有资源，有用户，有技术，有生态，但真正落到产品上，经常像隔着一层玻璃。

你知道它肯定能做。

但你不知道它什么时候真做。

字节不太一样。

它给我的感觉是，一旦看到一个方向被验证，它会非常快地把它产品化，然后塞进自己的体系里。

比如 Trae Work。

它不是单纯说，我给你一个代码补全。

它的方向更像是，你告诉我你要做什么，我来拆任务，我来调工具，我来整理项目文件，你少一点搬运，多一点判断。

这听起来很像废话。

但你自己真做过项目就知道，这里面最烦的不是写某一行代码。

最烦的是上下文到处飞。

需求在飞书里，设计稿在别的地方，代码在本地，接口文档在云文档，讨论在群里，截图在聊天记录里，部署又在另一个平台。

一个人做项目的时候，真正消耗你的，经常不是智力，而是搬运。

把这段话复制到那里。

把这个文件传上去。

把这个结果再截图回来。

把刚刚的需求重新解释一遍。

尼玛。

有时候我都怀疑，人类发明电脑这么多年，就是为了把自己训练成一个更熟练的复制粘贴机器。

所以当一个产品开始强调 Workspace，强调项目文件都在一起，强调从任务到执行再到交付都尽量在一个空间里完成，我会觉得这个方向是对的。

不是说它现在已经完美。

我也不觉得任何一个 Agent 工作台现在已经完美。

但方向很对。

这也是 AI 从玩具变成生产力时，迟早要跨过去的一步。

![Trae Work 多场景办公任务](/images/posts/2026-06-19-bytedance-ai-work-network/image-03-trae-work.png)

回到扣子。

扣子这个产品，挺有意思。

最早很多人知道扣子，可能是因为它能搭智能体，能做 Bot，能编排工作流。

那时候它更像一个 Agent 开发平台。

你可以在里面搭一个东西，让它调用知识库，调用插件，按你设定的流程去完成任务。

这个阶段我觉得它好用，但也没有特别意外。

因为那时候所有人都在做 Agent 平台。

但后面扣子开始往桌面端走，往编程项目走，往视频项目走，往 Agent World 走，事情就开始变得不一样了。

我打开扣子桌面端以后，最直接的感受就是，它想把一大堆 AI 场景放到同一个入口里。

聊天，写作，编程，视频，Agent 编排，技能商店，本地文件，云设备，行业技能，团队协作。

它不是在问你，你要不要跟一个 AI 聊天。

它更像是在问你，你现在到底想完成什么事。

想做一个网页，可以进编程项目。

想做一段视频，可以进视频项目。

想组织一堆 Agent 干活，可以进 Agent 协作。

想解决某个行业任务，可以加载对应技能。

想让本地文件也被处理，可以走桌面端。

这一下给我整得有点懵。

![扣子桌面端对话界面](/images/posts/2026-06-19-bytedance-ai-work-network/image-02-coze-desktop.png)

因为这个变化背后，其实是 AI 产品形态的一次转向。

过去两年，我们习惯了一个输入框。

所有事情都从 Prompt 开始。

你想写文章，就把需求打进去。

你想写代码，就把需求打进去。

你想做视频，也把需求打进去。

输入框像一个万能入口，但问题是，它也把很多压力交给了用户。

你要知道怎么描述。

你要知道该找哪个模型。

你要知道怎么组织上下文。

你要知道失败以后怎么改。

说实话，这对普通人并不友好。

很多朋友不是不想用 AI。

是不知道第一句话该怎么说。

而扣子这类产品正在做的事，是把很多场景提前摆出来。

你不需要从一片空白开始。

你可以从一个项目开始，从一个技能开始，从一个 Agent 开始，从一个行业包开始。

这玩意很像当年手机 App 取代网页入口的过程。

早期互联网大家什么都靠搜索框。

后来移动互联网起来以后，你要打车就打开滴滴，要点外卖就打开美团，要拍短视频就打开抖音。

入口变得更具体。

动作也变得更短。

AI 现在也在经历类似的事。

不是所有人都需要一个万能聊天框。

很多人需要的是，打开以后就知道自己该干什么。

字节系现在最值得看的地方，恰好就在这里。

它不是只有模型。

它有产品，有生态，有用户场景，有内容平台，有办公平台，有云服务，有开发工具。

这几个东西串起来以后，力量是不一样的。

飞书这条线，我觉得尤其值得聊。

飞书在 OpenClaw 爆火的时候，很快推出了可以连接 OpenClaw 的官方插件，后面又有飞书 CLI，让 AI Agent 可以操作飞书里的消息、日历、文档、表格这些东西。

这件事我当时看到的时候，其实挺兴奋。

因为它解决的是一个非常现实的问题。

AI 不能只停留在对话框里。

对话框再聪明，如果它永远只能给你建议，不能进到你的工作现场里干活，那它和一个特别会说话的顾问没有太大区别。

真正有用的，是它能读你的云文档，能写你的文档，能查你的日历，能建你的表格，能在你的协作空间里完成动作。

这才是打工人真正想要的东西。

你想想看。

你早上打开飞书，里面有一堆消息，有会议纪要，有待办，有产品需求，有客户反馈，有日报，有表格。

如果 AI 只是告诉你，我建议你整理一下。

那我谢谢它。

我当然知道我应该整理一下。

问题是我不想整理。

我想要的是，它直接帮我把会议内容整理成文档，把待办拆出来，把表格建好，把相关资料归到一个地方，然后告诉我，哥，今天你先看这三件事。

这才叫真的有用。

这也是飞书生态在大模型时代的价值。

它本来就承载了很多公司的真实工作流。

AI 一旦能以比较自然的方式接进去，就不是一个外挂，而是工作系统里长出来的一部分。

这点和单纯做一个聊天产品，很不一样。

当然，字节系也不是没有问题。

我自己现在最大的槽点，还是开放性。

比如有些产品不太支持用户自由接入其他模型。

国内版本里多个模型轮调，你很多时候也看不到自己到底调的是哪个模型。

付费方式也更偏向自家的模型和服务。

这件事对普通用户可能没那么敏感。

但对重度用户，尤其是开发者来说，会有点难受。

因为我们这帮人已经被 Claude、Gemini、OpenAI、Qwen、DeepSeek 这些东西养刁了。

不同任务会想用不同模型。

写代码可能想用 Claude。

做长上下文可能想用 Gemini。

中文材料可能想试豆包或者 Qwen。

做推理可能想换另一个。

你突然告诉我，别选了，我们帮你安排。

我会有点不安。

不是哥们。

你至少让我知道我现在坐的是哪班车吧。

但这个问题，我觉得也要分人群看。

对专业开发者来说，透明度和可配置性很重要。

对普通办公人群来说，它可能真的没那么重要。

很多人其实不关心自己调用的是哪个模型。

他只关心，文档能不能写好，表格能不能生成，视频能不能出片，小程序能不能跑起来，代码能不能部署。

如果结果稳定，入口简单，价格能接受，生态能接上，他就会用。

这就是字节系有机会的地方。

它不是只在服务极客。

它在服务大量没有时间研究模型榜单，但真的想把 AI 用起来的人。

而这个人群，可能比我们想象的大得多。

我有时候觉得，AI 圈子里有一个很大的误判。

我们会把自己看到的世界，当成所有人看到的世界。

我们天天刷 X，刷 GitHub，刷 Hacker News，讨论 Claude Code 又升级了什么，Codex 又支持了什么，OpenAI 又发了什么 API。

但很多普通用户不是这样的。

他可能不知道 Claude Code。

他可能也不知道 MCP。

他甚至可能连 API Key 是什么都不想知道。

他只是想问，有没有一个东西，能帮我把活干完。

就这么简单。

这时候谁离他的工作现场更近，谁就更有机会。

字节离这个现场很近。

抖音是内容现场。

飞书是办公现场。

火山引擎是企业服务现场。

豆包是普通用户的聊天入口。

即梦和 Seedance 是视频创作现场。

Trae 是开发现场。

扣子是 Agent 和项目现场。

这些东西如果各自为战，当然也就那样。

但如果它们真的能越来越深地连在一起，那就不是一个产品矩阵那么简单了。

那是一张网。

大模型时代最值钱的，可能不是某一个按钮。

而是谁能把模型、工具、数据、场景、分发、协作这些东西连成一条普通人能走的路。

说到视频这块，Seedance 2.0 也挺典型。

字节做视频生成，不只是因为它有模型团队。

更关键的是，它有抖音，有 TikTok，有即梦，有海量短视频创作经验，有真实用户每天对视频内容的反馈。

这个积累挺吓人。

视频生成不是只比谁能生成更高清。

它还要理解节奏，镜头，转场，主体一致性，内容消费习惯，平台分发逻辑。

这些东西听起来很虚，但做内容的人都知道，它们一点都不虚。

一个 15 秒视频，好不好看，有时候就是前 1 秒的钩子，第三秒的转折，第七秒的视觉刺激，结尾那一下情绪。

这不是单纯堆算力就能解决的。

所以当字节把视频模型、内容平台、创作工具放在一起看的时候，我会觉得它在 AIGC 视频上有一张很好的底牌。

当然，优势不是胜利。

大公司也会犯错。

生态太大，也容易内部打架。

产品太多，也容易让用户搞不清楚到底该用哪个。

扣子，豆包，飞书，Trae，火山，剪映，即梦，这些东西之间到底怎么分工，未来能不能真的顺滑协作，还是会变成一堆入口互相抢用户，这个我也不确定。

说实话我也还在观察。

但我看好它的原因，不是因为它现在所有东西都做好了。

而是因为它站的位置很对。

它没有只盯着模型参数。

它也没有只做一个炫技 demo。

它在往真实工作和真实创作里扎。

这个方向，在国内尤其有价值。

因为国内用户使用海外 AI 产品的成本，短期内很难彻底消失。

网络，账号，支付，语言，合规，生态，数据安全。

每一个都是门槛。

对少数极客来说，这些都能解决。

但对绝大多数人来说，门槛就是门槛。

你不能指望每个运营都去配置 Claude Code。

你不能指望每个产品经理都去研究 Codex CLI。

你也不能指望每个小老板都知道怎么把 MCP 接进自己的知识库。

他们需要的是一个更简单的入口。

这也是我为什么觉得，办公人群真的可以试一下字节系这套东西。

不是说它一定比海外所有产品都强。

不是。

但在国内语境下，它可能是更容易开始的那条路。

你可以用 Trae 处理开发任务。

![Trae Code 开发任务界面](/images/posts/2026-06-19-bytedance-ai-work-network/image-04-trae-code.png)

你可以用扣子做 Agent 和项目。

你可以用飞书 CLI 把 AI 接到自己的办公文档和日程里。

你可以用豆包做日常问答和内容辅助。

你可以用即梦和 Seedance 做视频创意。

你甚至可以把这些东西慢慢串起来，变成一套适合自己的工作方式。

一开始可能会有点乱。

产品多，入口多，名字也多。

而且有些地方肯定还不够顺。

但我觉得，真正重要的不是第一次就把所有东西摸透。

而是你开始意识到，AI 不再只是一个网页里的聊天框。

它正在进入你的工作台，你的文档，你的代码，你的视频，你的协作空间。

这件事挺大的。

我突然想到了十几年前的移动互联网。

那时候大家也会讨论，哪个 App 更好，哪个入口更强，哪个平台更开放。

但几年之后回头看，真正改变生活的，不是某一个 App 的某一个功能。

而是手机把地图、支付、社交、内容、购物、办公都装进了一个随身系统里。

人不是因为一个功能迁移过去的。

人是因为生活慢慢被一整套系统包住了。

AI 现在可能也在走到这个阶段。

从一个聪明的对话框，变成一个无处不在的工作层。

谁能把这个工作层做得足够低摩擦，足够贴近日常，谁就有机会吃到最大的一波红利。

字节现在很像那个正在疯狂铺路的人。

路还没铺完。

有些地方坑坑洼洼。

有些路口标识还不清楚。

有些车还不让你自己选发动机。

但它确实在铺。

而且铺得很快。

所以我才会说，大模型时代，我很看好字节系。

不是因为它每个产品都完美。

也不是因为它已经赢了。

而是因为它做对了一件事。

它没有把 AI 当成一个孤零零的按钮。

它在把 AI 接进真实的人，真实的工作，真实的内容，真实的协作里。

这件事如果真的成了，影响会非常大。

对普通人来说，可能不用再纠结什么模型最好，什么工具最强，什么配置最先进。

你只需要打开一个你本来就在用的工作空间，然后把更多事情交给 Agent。

对开发者来说，可能也不用在十几个产品之间来回横跳，而是让项目、代码、文档、部署、协作慢慢靠近同一个空间。

对内容创作者来说，文字、图片、视频、分发、复盘，也会越来越像一条连续的生产线。

我不知道字节最终能做到什么程度。

但现在这个阶段，它确实是国内少数让我看到完整野心的公司。

而且这个野心不是写在 PPT 里。

是写在一个个已经能打开、能下载、能体验的产品里。

这就很难得。

大时代啊，朋友们。

很多时候，我们以为真正的变化会以一个超级模型的形式出现。

一个发布会。

一个榜单第一。

一个震惊全网的 demo。

但更真实的变化，可能没那么戏剧化。

它可能就是某一天，你打开扣子桌面端，发现里面已经有 Agent World 了。

你打开飞书，发现 AI 真的能接进文档和日程了。

你打开 Trae，发现它不只是补代码，而是开始替你组织项目了。
