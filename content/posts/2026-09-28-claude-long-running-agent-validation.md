Anthropic 9 月 25 日披露：Claude 在面向科研的 Claude Science 环境里连续运行数天，完成了平面 N=4 超杨-米尔斯理论六粒子散射振幅的九圈计算。这比 2023 年公开的八圈结果再前进一步。

这不是一则“AI 替代科学家”的快讯。更值得开发团队注意的是：一个长时、步骤脆弱、任何一处出错都会使结果失效的任务，已经能由 Agent 推进到可交付的结果；但它之所以值得相信，靠的不是“运行了很久”，而是两条计算路径得到一致答案、专家复核，以及可被外部读取的结果文件。

对在做编码 Agent、研究自动化或运营自动化的团队，这带来一个更现实的问题：当 Agent 从几分钟任务走向数天任务，验收应该怎样改？

## 先把这件事说清楚：Claude 算出了什么

散射振幅可以理解为：物理学家用来计算粒子相互作用结果概率的一类公式。“圈”代表逐层加入的高阶修正；每多一圈，计算规模和出错风险都会急剧上升。此次对象是理论物理中的平面 N=4 超杨-米尔斯模型，它是用来检验方法的高度对称模型，并不是直接描述现实粒子世界的最终理论。

Anthropic 的科学博客把这次工作描述为：两位物理学家给出一条简短任务说明后，让 Claude 持续推进；它一条路直接使用自举法，另一条路先计算相关的形状因子，再通过已有的对偶关系映射回振幅。两条路对比时得到一致结果。

这里有三个不能省略的限定：这不是凭空提出新物理定律，而是把已知方法和工程流程推进得更远；这不是没有人类验证，曾参与八圈结果的 Lance Dixon 对结果做了独立检查；这也还不是同行评审论文的终点，结果数据已公开，但计算程序尚未随之公开。

适合带走的结论不是“给 Agent 一句提示就行”，而是：长任务的价值，取决于它能否留下可复算、可比较、可追责的中间与最终证据。

## 真正的门槛，从模型能力变成任务编排

报道提到，直接自举计算使用 Python 与 SymPy，约相当于 96 个 CPU 运行一周；完整路线面向普通用户的成本估计约为 1,000 至 2,000 美元，主要是长期使用模型的成本。数字本身不应被套用到一般业务，但它揭示了一个产品事实：长时 Agent 的成本不是一次调用单价，而是“持续运行 × 返工 × 验证”的总账。

短任务常用的“输出看起来对”到了长任务会失效。因为它可能在第 30 步误读一份文件、第 70 步覆盖关键配置，最后仍能写出一段流畅总结。任务拉长后，至少要把验收拆成三层：

| 验收层 | 要验证什么 | 可落地做法 |
| --- | --- | --- |
| 过程层 | 是否沿着允许路径执行 | 记录工具调用、输入版本、权限变化与关键决策 |
| 结果层 | 是否得到任务定义的输出 | 用结构化断言、测试集或业务规则检查交付物 |
| 独立层 | 是否只是“自己证明自己” | 用第二条实现路径、独立模型、人工抽检或外部系统复核 |

九圈计算的两条路径，恰好对应了第三层。业务里未必值得每件事都跑两次，但高影响动作至少要明确：谁负责独立检查、检查什么、失败后回滚到哪一步。

还要把“任务完成”拆成两个时间点：Agent 声称完成，和系统接受结果。前者可以由模型自行报告；后者必须由事先定义的检查器、外部状态或责任人触发。把两者混为一谈，会让团队把一篇漂亮总结误当成一次可靠交付。文件生成、接口返回 200、页面出现提示，都不等于下游已经收到正确结果。

## 别把“无人值守”当成上线标准

“无人值守运行数天”很吸引人，却容易把团队带向错误指标。对业务系统来说，真正需要先定义的是：无人干预到什么边界，才是安全的？

例如，一个代码 Agent 可以无人值守地整理测试失败、开分支、生成修复建议；但把它的边界扩展到直接合并、部署或修改生产数据，验收要求就会完全不同。一个研究 Agent 可以自己检索、写脚本和做对比；但引用结论进入对外报告前，仍应保留来源核验和人工签字点。

建议把长时 Agent 任务设计成四个关口：

1. 开始前写出成功条件：交付物、禁止动作、预算和终止条件。
2. 把检查点放在不可逆动作前：合并、发送、支付、发布、删除或生产写入都要求显式确认。
3. 为关键结论安排独立证据：另一套测试、只读系统回查、不同模型复算，或有上下文的人类抽检。
4. 保存失败轨迹：保留中间产物、环境版本和失败原因，以便从失败处续跑。

这四个关口也能控制成本。没有停止条件的长跑会把模型调用、工具调用和人工回看一起放大；有了预算上限、超时阈值和升级路径，系统就能在证据不足时停在可恢复状态。先把一项流程做成“小范围、可复核、可停止”的试点，比直接追求全天候自主更容易得到可比较的数据。

## 对开发团队的一个实际判断

这次结果最值得关注的，不是“AI 已经能做九圈物理”，而是长时 Agent 的评估单位正在变化：从一次回答是否漂亮，转向一段执行过程是否可靠。

如果你的团队正在评估长时 Agent，下一轮试点不妨选一个已有明确正确答案、但人工执行很繁琐的任务。先限制权限，建立过程日志和结果断言，再增加独立复核。这样测到的不是演示效果，而是它在真实工作流里能否被信任。
