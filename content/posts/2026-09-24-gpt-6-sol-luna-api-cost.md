9 月 22 日，OpenAI 发布 GPT-6 Sol 和 GPT-6 Luna，并称两款模型的 API 价格比 GPT-5.6 对应型号的促销价低 50%。开发者最该关注的不是“便宜一半”这句发布语，而是：相同任务是否仍能达到原来的质量，完成一次任务实际花费又变了多少？

这次变化直接影响调用量大的 AI 产品、编码 Agent 和内部自动化团队。现在适合做一次小规模复测，把模型切换从“看每百万 token 单价”改为“看每个合格结果的成本”。

## 先把价格口径看清楚

OpenAI 公布的短上下文标准处理价格如下，单位是每百万 token：

| 模型 | 输入 | 输出 |
| --- | ---: | ---: |
| GPT-5.6 Sol | $4 | $20 |
| GPT-6 Sol | $2 | $10 |
| GPT-5.6 Luna | $0.20 | $1.20 |
| GPT-6 Luna | $0.10 | $0.50 |

“便宜一半”比较的是 GPT-5.6 的促销价格，不是它最初发布时的常规价格。并且 Luna 的输出价格从 $1.20 到 $0.50，实际降幅超过一半。对长上下文请求、缓存写入、数据驻留或 Fast mode，费率会不同；成本估算应对照自己正在使用的具体档位，不能直接拿一张价目表套所有流量。


API 标价也不等于一笔业务请求的总成本。一个客服分类调用可能只消耗少量 token；一个编码 Agent 则可能反复读取仓库、调用工具、重试并生成很长的补丁。真正要比较的是完成同一项工作、达到同一验收标准后的账单。

模型还可能用不同长度的回答完成同一任务。若新模型输出更长、触发更多工具调用，或者质量不足需要重试，省下的输入、输出单价会被额外消耗抵消；反过来，如果模型用更少步骤交付可用结果，任务总成本下降可能超过 token 价差。缓存命中、上下文长度和服务档位也会改变实际账单。预算表应按输入、缓存输入、输出、工具调用与返工分项记录，至少取一次线上账单核对估算。

## 独立评测给出的不是“全线升级”

Artificial Analysis 的独立评测大体支持一个更谨慎的结论：成本效率有进步，但能力变化因任务而异。

在其 Coding Agent Index 中，GPT-6 Sol 比 GPT-5.6 Sol 高 2 分，评测中的单任务成本约减半。Luna 的成本也下降，但该指数分数比前代低 2 分。对写代码团队来说，Sol 值得进入候选；Luna 更需要按具体任务检查质量，不能仅凭低价直接替换。

知识工作评测也出现回退。Artificial Analysis 指出，两款新模型在 GDPval-AA v2.1 中的分数下降；Luna 在 AA-Briefcase 的分数也有回落，常见问题是交付物展示质量较弱、遗漏评分要求。换句话说，短小明确的执行任务和需要完整、精致交付的工作，可能得出不同的模型选择。

OpenAI 自己报告了更积极的内部结果，例如 Sol 在其内部事实性评测中的错误数约减半。不过这组测试取自用户曾标记错误的对话，并不代表所有真实场景；评测条件和产品里的提示词、工具配置也可能不同。它适合作为测试假设，不该替代团队自己的验收数据。

## 三类任务值得先重测


**第一类：边界清楚的编码和工具调用。** 选取过去真实完成的缺陷修复、代码审查或固定流程任务，保持提示词、上下文、工具和验收规则一致，分别跑旧模型与新模型。除通过率外，记录重试数、人工修改时间、最终补丁是否可合并，以及每个合格结果的成本。Sol 的独立编码评测进步和成本下降，让这类任务适合作为首批试点。

**第二类：长输出与知识工作交付。** 挑选需要分析资料、写完整方案、整理表格或生成用户可读报告的任务。重点查输出是否漏掉必需章节、关键证据和格式要求，不要只看答案是否“读起来不错”。如果输出变短但缺项变多，单价下降可能被人工补做抵消。

**第三类：高频、低风险的批处理。** 摘要、字段抽取、简单分类等可以先抽样回放一小批脱敏数据，核对准确率和异常分流，再逐步增加比例。对于不能接受错分的场景，保留旧模型或人工复核的兜底路径，观察到的节省应以处理完成率为前提。

复测时至少保留三项指标：任务成功率、人工介入时间、每个合格结果的总成本。再按任务类型统计，而不是把所有请求混成一个平均值。这样才能识别“API 单价下降了，但因为重试或返工而没有省钱”的情况。

如果团队没有成熟评测集，可先从近期真实请求中抽取一小批样本，按简单、常见和失败难例分层，脱敏后并行跑旧、新模型。每个任务使用相同的输入和工具权限，并让不知道模型名称的评审按同一份清单打分。样本不大时不要只看平均分；同时查看错误类型和单项任务差异，再把通过的任务类型逐步灰度。这个过程成本低，也能先暴露模型对提示词、上下文和工具链的敏感点。

对外部用户有影响的功能，还要保留监控和回退条件。比如成功率连续低于现有模型、人工复核率上升，或某一类关键错误增加，就暂停扩量并回切旧路由。低价模型可以负责初筛，再把低置信度、格式异常或高风险结果交给更强模型或人工检查；前提是路由条件可观察、复核结果能回流，而不是把“多模型”变成无法追责的黑箱。

## 把降价变成可验证的路由调整

团队可以先从一周的历史请求中抽取几十个代表任务，固定输入与验收标准，做并行对照。若新模型通过率不降、人工修改没有增加，再把该任务类型逐步切过去；若结果变差，就保留高质量模型或升级人工审核。测试集中既要有日常简单任务，也要有长上下文和难例，避免只挑新模型擅长的样本。

GPT-6 Sol 与 Luna 的明确变化是 API 标价下降，独立评测则提醒我们：Sol 的编码成本效率更有吸引力，Luna 和知识工作仍需要按场景验证。**先重测任务，再调路由；先算合格结果成本，再谈省下多少。**
