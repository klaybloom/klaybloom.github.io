9 月 28 日，NVIDIA 公布 Open Agent Safety Platform：用 OpenShell 在 Agent 运行时外侧执行访问策略，并以 Sentry 参考设计持续监控、隔离越界行为。对正在把编程 Agent、客服 Agent 或自动化流程接入真实系统的团队，值得关注的不是“Agent 终于安全了”，而是权限控制开始从提示词和应用代码，向运行环境与硬件监控延伸。

现在就可以做一件具体的事：找一个已有 Agent，分别测试它能读写哪些文件、能连接哪些网络目的地、能否取到不属于当前任务的凭证。若边界只靠系统提示词或 Agent 自己遵守，就还没有形成可验证的安全控制。

## 这次发布改变了什么

OpenShell 是开源的安全运行时。NVIDIA 将它定位为模型和 Agent harness 之外的一层控制：按策略限制 Agent 对文件、网络、工具和凭证的访问，并记录允许或拒绝的决定。官方资料称它可以支持开源和闭源模型，也能扩展到 Arm、Intel 等第三方计算平台。

平台参考设计还包括 Sentry：运行在 BlueField-4 DPU 上的带外监控与执行层。NVIDIA 称，当 Agent 试图越过设定边界时，Sentry 可以隔离并停止它。两者承担的角色不同：OpenShell 管运行时访问，Sentry 则提供独立于 Agent 进程的观察和遏制路径。


这不是“装上就安全”的证明。NVIDIA 公布的是软件平台和参考系统设计，并称已有超过 100 家组织参与相关技术生态；这些信息说明方案正在落地，却不能替代每个团队自己的威胁建模、策略审查和故障演练。AP 报道也指出，传统网络安全的最小权限原则仍难落地：Agent 要完成工作就需要真实资源，但怎样给它足够而不过量的权限，并不简单。

## 为什么权限要放在模型之外

Agent 的任务描述往往很宽：“修复这个仓库”“查找资料并整理报告”“处理这批工单”。它可能通过工具调用、脚本或多轮规划，把一个目标拆成开发者没逐项预设的动作。模型可以被诱导、产生错误判断，也可能遭遇恶意网页或仓库内容；让模型在提示词里承诺“不做越权操作”，并不能阻止它真的发起系统调用。

所以安全边界要落在 Agent 无法自行改写的地方。运行时可以拒绝未授权的文件访问和网络请求，凭证代理可以只在规则允许时提供密钥，独立监控则能在异常时暂停任务。它们不能保证模型永远判断正确，但能把“判断失误”与“造成不可逆影响”隔开。

这也改变了评估 Agent 的方式。过去常测“它能不能完成任务”；现在还要测“它为了完成任务尝试了什么”“拒绝后会不会换路径”“策略与凭证是否真的挡住了越界”。安全指标不是单看任务成功率，还要检查越权尝试是否被拦截、拒绝是否留痕、人工接管能否生效。

## 团队先测三条边界


**一、文件边界。** 给 Agent 一个只包含任务所需目录的工作区，尝试让它读取工作区外的 SSH 密钥、环境配置或其他项目文件；再试写入不应修改的目录。确认拒绝发生在运行时，而非仅由模型口头表示不做，并检查审计记录是否包含路径、动作和结果。

**二、网络边界。** 默认关闭无关出站访问，只允许任务依赖的域名或服务。用重定向、子域名、短链、DNS 查询等情况检查规则有没有绕过路径。对于需要网页搜索或 API 的 Agent，逐个核实可连接目标、方法与路径，避免“需要联网”变成全网通行。

**三、凭证边界。** 不把长期密钥直接放在 Agent 可读的环境变量或文件里。让权限代理按任务提供短时、最小范围的凭证，并尝试让 Agent读取、复制或用于另一个服务。要验证拒绝和轮换，而不只是密钥在界面上被隐藏。

每个测试至少记录四项：预期允许的动作、预期拒绝的动作、实际结果、日志证据。再增加一次故障演练：策略服务不可用、Agent 持续重试或尝试换工具时，系统是默认拒绝、暂停等待，还是悄悄扩大权限？答案应由团队事先决定并写入运行手册。

测试时要留一组正常任务作为对照，避免策略把越权挡住的同时也让正常工作无法完成。每次改动规则，都用同一批正向与负向用例复测，并记录策略版本、Agent 版本、工具范围和失败原因。若拒绝没有日志、日志无法关联到具体任务，或管理员可以绕过隔离直接发放密钥，这条边界就还不能算通过。先在只读任务验证，再逐步开放写入和外部调用；每一步都要有明确回退方式。

## OpenShell 值得试，但要带着问题试

如果你的团队已在运行命令行编程 Agent 或内部自动化，优先从非生产环境和只读任务开始。先列出工作区、依赖站点、需要调用的 API 与密钥，再将其变成允许清单；随后构造超范围读取、越权联网和跨任务复用凭证的负向测试。保留策略版本和审计日志，确保安全团队能复现一次拒绝决策。

评估时还要看兼容性与运维成本：Agent harness 是否能被运行时包裹，规则能否由平台团队统一管理，策略变更如何审查，拒绝事件怎样进入现有告警系统。OpenShell 的开源与跨平台方向降低了试验门槛，但“能够运行”不等于“策略适合业务”，更不等于完成了组织级安全验收。

**结论：** NVIDIA 这次发布让 Agent 安全有了更明确的工程落点——把权限执行移到模型之外，并为越界行为增加独立监控。团队现在就能按文件、网络、凭证三条边界做负向测试；能否挡住真实越权尝试，比演示任务跑得多顺更重要。
