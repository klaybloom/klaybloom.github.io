![封面图：企业智能体安全边界](/images/posts/2026-05-21-claude-hosted-agents-enterprise/cover.png)

过去一年，很多团队聊智能体时，最容易被演示打动：它会写代码，会操作网页，会调用工具，会自己处理一串任务。

但真到企业里落地，问题会立刻变得具体：

代码仓库能不能离开公司网络？数据库要不要暴露到公网？代理执行命令时，运行环境归谁管？出问题以后，审计日志在哪里？

Anthropic 在 2026 年 5 月 20 日这份 AIHOT 日报里出现的更新，正好打在这些问题上：Claude Managed Agents 新增自托管沙箱和 MCP 隧道。

这不是一个单纯的模型升级。它更像是企业智能体从“云端助手”走向“受控执行系统”的信号。

## 这次更新到底是什么

Anthropic 官方博客把这次更新拆成两部分：

第一，自托管沙箱。企业可以让代理的工具执行环境运行在自己的基础设施里，也可以交给 Cloudflare、Daytona、Modal、Vercel 这类托管沙箱提供方处理计算和隔离。

第二，MCP 隧道。它让 Claude Managed Agents 连接企业私有网络里的 MCP servers，例如内部数据库、业务 API、私有工具服务，而不用把这些服务直接暴露到公网。

官方状态也值得注意：自托管沙箱是 public beta，MCP 隧道是 research preview。前者已经面向更广的企业试用，后者还处在更早阶段。

![正文配图：托管代理架构变化](/images/posts/2026-05-21-claude-hosted-agents-enterprise/image-01.png)

这里的关键点不是“Claude 又多了两个功能”，而是托管代理的责任边界被重新划分了。

代理的大脑、编排、上下文管理、错误恢复仍然可以在 Anthropic 的平台上；但真正接触代码、文件、包、内部服务的那一层，可以回到企业自己的边界内。

对开发者和产品团队来说，这个变化很现实：你不必在“完全托管很方便”和“敏感资产不能出去”之间二选一。

## 为什么这件事值得中文团队关注

很多中文 AI 创业团队正在做两类产品。

一类是面向开发者的 agent：自动修 bug、改代码、查日志、生成测试、接入 CI。

另一类是面向企业业务的 agent：查 CRM、处理工单、跑财务流程、写报告、调用内部系统。

这两类产品都会遇到同一个门槛：用户愿意让 AI 参与工作，但不一定愿意把生产数据、内部 API、客户资料、代码仓库交给外部平台。

自托管沙箱和 MCP 隧道给出的方向，是把“智能体能力”和“企业安全边界”分开设计。

模型平台提供推理和任务编排，企业保留执行环境、网络策略、日志系统、运行镜像和资源规格。这样一来，采购、法务、安全团队更容易评估风险，研发团队也能保留现有工程规范。

这对创业公司尤其重要。过去很多 AI 应用在 demo 阶段很强，但一进企业采购流程就卡住。不是产品不会做事，而是权限、数据、审计、网络访问说不清。

现在大厂开始把这些能力产品化，说明下一阶段企业智能体的竞争，不会只看模型多聪明，还会看执行环境能不能被信任。

## MCP 隧道改变的是内网工具接入方式

MCP 这件事，本质上是给模型和工具之间定义一个更统一的连接方式。

但企业内部服务通常不适合直接放到公网。过去如果要让代理调用内部工具，常见做法是写一堆中间层、开专线、配网关、做权限映射，还要担心每个工具的接入方式都不一样。

MCP 隧道的价值在于：代理可以通过轻量网关访问私有网络里的 MCP servers。内部服务仍在企业网络中，外部平台不需要直接拿到数据库或 API 的公网入口。

![正文配图：MCP 隧道访问内网资源](/images/posts/2026-05-21-claude-hosted-agents-enterprise/image-02.png)

对产品经理来说，这会影响企业版产品设计。你不能只写“支持内部工具调用”，还要回答三个问题：

1. 工具运行在哪里？
2. 数据经过哪里？
3. 谁能查看和限制代理的行为？

对开发者来说，这意味着未来的 agent 产品更可能围绕 MCP 做插件生态。不是每个客户都单独写一套集成，而是把内部能力包装成可控的 MCP server，再通过隧道接入。

## 自托管沙箱让执行环境回到企业手里

智能体真正有用时，往往需要执行命令：安装依赖、读文件、调用脚本、跑测试、处理图片、访问仓库。

这也是安全团队最敏感的部分。因为模型说什么不重要，最终影响系统的是它执行了什么。

自托管沙箱把这部分移到企业可控环境里。企业可以设置运行镜像、资源规格、网络策略和审计工具。需要重计算的任务，比如长时间构建、视频处理、图片处理，也可以按自己的基础设施来配置。

这对开发者工具是一条很清晰的产品线索：以后企业不会只问“模型准确率多少”，还会问“执行环境能不能接入我们的安全体系”。

## 给创业者和团队的三个判断

第一，企业智能体会从“功能演示”进入“基础设施对接”阶段。

会写文档、会写代码、会点按钮，只是入口。真正签企业客户时，安全边界、审计、权限、网络接入会变成必须回答的问题。

第二，MCP 生态值得更早布局。

如果你的产品要连接一批企业内部系统，提前按 MCP server 的方式组织工具，会比每个客户单独写集成更容易扩展。哪怕暂时不用 Claude Managed Agents，这种接口设计也更利于之后接入不同代理平台。

第三，企业版定价可以围绕“受控执行”重新设计。

普通 SaaS 只卖席位或调用量。agent 产品还可以围绕沙箱规格、并发任务、内网连接、审计保留、私有工具数量来定价。这些能力更贴近企业采购愿意付费的部分。

## 今天的信号

这次更新的真正意义，是把智能体落地里最难讲清的部分摆到了产品页面上：代理在哪里运行，工具怎么访问，数据边界由谁控制。

中文团队如果正在做 agent 产品，建议不要只盯着模型榜单和单次任务效果。更值得提前设计的是企业客户上线前一定会问的那张表：权限、网络、日志、沙箱、数据流向、失败处理。

AI 应用越来越像软件基础设施。能进入生产环境的，不只是会回答问题的模型，而是能被企业管理起来的执行系统。
