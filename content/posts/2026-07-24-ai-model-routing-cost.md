过去一年，很多团队用 AI 的方式很粗放：把最强模型设成默认值，然后祈祷账单不要涨得太快。

这在原型阶段没问题。问题是，一旦 AI 功能进入真实业务，用户请求会变得非常杂：有人只是改一个按钮文案，有人要重构模块，有人要理解长文档，有人要生成一整套方案。

如果这些请求都走同一个高价模型，产品看起来很先进，财务表会越来越难看。

7 月 23 日 AIHOT 日报里，Cursor Router、GitHub Copilot 的计费解释、GigaToken 的高速分词器，以及 OpenAI、Anthropic、Google 继续加码 AI 基础设施，实际上都指向同一个变化：

**AI 产品开始从“谁的模型更强”，转向“每个任务该用哪种智能”。**

## 模型路由正在变成产品能力

Cursor 发布的 Cursor Router，是今天最值得产品团队认真看的更新。

它不是再加一个模型按钮，而是让系统先判断请求的上下文、复杂度和任务类型，再把请求交给更合适的模型。

Cursor 给出的测试结果很直接：Auto Intelligence 模式在接近高端模型体验的同时，团队成本大约低 60%；Auto Balance 模式在用户满意度上超过 Opus 4.8，同时成本低约 36%。

这件事对创业团队的启发是：模型选择不应该只暴露给用户，也不应该完全交给用户自己猜。

一个正常的 AI 产品，至少会遇到四类任务：

| 任务类型 | 常见场景 | 更合理的策略 |
|---|---|---|
| 低风险短任务 | 改写、分类、摘要、格式化 | 便宜快模型 |
| 稳定重复任务 | 客服回复、表单抽取、轻量代码修改 | 固定模型加缓存 |
| 高价值复杂任务 | 长代码改造、复杂分析、重要文案 | 强推理模型 |
| 失败成本高任务 | 财务、权限、生产操作建议 | 强模型加验证流程 |

如果你的产品还只有一个“使用 GPT-5.6 / 使用 Opus / 使用某某大模型”的开关，本质上是把调度责任甩给了用户。

真正的产品化，是把这个判断放回系统里。

## 成本不是 token 价格这么简单

GitHub Blog 这次讨论 Copilot 与直接 API 调用的差异，也说出了很多团队容易忽略的事实：用户为 Copilot 支付的，不只是模型 token，还包括编码工作流、策略管理、工具集成、上下文组织和企业管控。

这句话放到任何 AI 产品里都成立。

如果一个团队只盯着模型 API 单价，很容易做出错误判断。便宜模型如果让用户多试三次，真实成本可能并不低；贵模型如果一次完成高价值任务，也可能更划算。

所以 AI 产品的成本表不能只有“输入 token、输出 token、模型单价”三列，还要加上：

- 用户是否接受结果
- 结果是否进入业务流程
- 是否需要人工返工
- 是否触发二次调用
- 是否用了缓存
- 是否用错了模型

Cursor 用用户满意度、代码保留率、cost per commit 这类指标衡量路由效果，这比单纯看每次请求花了多少钱更接近业务真实结果。

对国内创业团队来说，这也是一个提醒：不要只做“调用模型的壳”，要尽早建立自己的任务指标。

## 底层性能也会改变账本

日报里还有一个看起来偏工程、但意义很大的项目：GigaToken。

它是一个语言模型分词器，官方 README 里给出的 GPT-2 分词吞吐达到 24.53 GB/s，比 HuggingFace Tokenizers 快 989 倍，比 tiktoken 快 681 倍。它还支持 HuggingFace Tokenizers 和 tiktoken 的兼容模式，方便替换。

分词器不像大模型发布那么热闹，但它影响训练、数据处理、长上下文预处理、日志分析和批量评测。很多 AI 应用慢，不是只慢在模型推理，也慢在前后处理。

这类基础组件会让“单位智能成本”继续下降。

问题是，成本下降不会自动变成产品优势。只有当产品能把任务分类、模型路由、缓存、批处理、失败重试和质量验证连在一起，便宜下来的能力才会变成更高的毛利，或者更好的用户体验。

## 创业团队现在可以做三件事

第一，给每个 AI 功能标注任务等级。

不要只记录“用户调用了哪个模型”。要记录这个请求是摘要、改写、生成、检索、代码修改、规划，还是高风险决策建议。没有任务标签，就没有路由优化。

第二，建立自己的质量信号。

在编程工具里，可以看代码是否被保留、PR 是否通过、用户是否继续提问。在内容工具里，可以看是否被复制、是否被发布、是否被二次编辑。在客服工具里，可以看是否转人工、是否被用户追问。

这些信号会比通用 benchmark 更有用。

第三，把“默认最强模型”改成“默认合理模型”。

强模型应该用在高价值、高不确定性、高失败成本的地方。简单任务交给便宜快模型，重复任务交给稳定模型，批量任务优先考虑缓存和流水线。

这不是省小钱，而是让 AI 产品能真正规模化。

今天的 AI 基础设施新闻里，OpenAI、Anthropic、Google 都在投入更大的数据中心、更大的 GPU 采购和更长期的研究基金。大公司会继续把智能变强，也会继续把算力投入做大。

对创业团队来说，不能只等模型变强。

更重要的问题是：当智能越来越多、越来越便宜、越来越分层时，你的产品有没有能力把它用对。

下一轮 AI 产品竞争，不是每个请求都调用最贵模型。

而是每个任务，都拿到刚好够用、结果可靠、成本合理的那份智能。
