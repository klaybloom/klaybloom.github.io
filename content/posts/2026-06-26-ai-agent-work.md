昨天的 AI 日报里，有几条消息放在一起看，味道很明显。

豆包正式推出专业版，标准套餐连续包月 68 元，加强套餐 200 元，高级套餐 500 元。收费点不是“聊得更聪明一点”，而是接入豆包 2.1 Pro 的办公任务模式：操作本地电脑、使用浏览器、调用 Skills、定时任务、处理 Office 文档，甚至生成应用和网站。

同一天，Notion 把 Cursor SDK 接进了自己的协作场景。用户可以在文档里提到 Cursor，在讨论串里交代任务，或者把数据库里的 issue 指派给它。Cursor 负责规划、写代码、测试、验证，最后创建 PR。Google 也把 Computer Use 做进 Gemini 3.5 Flash，让开发者通过 Gemini API 构建能看屏幕、推理、操作浏览器、移动端和桌面的智能体。

这三件事合在一起，说明一个变化：AI Agent 的竞争，正在从“模型回答能力”转向“可交付的工作量”。

## 以前卖的是回答，现在卖的是执行时间

过去一年，很多 AI 产品的定价都围绕模型等级、上下文长度、次数限制。用户付费后，得到的是更好的回答、更长的文档处理、更少的排队。

豆包专业版这次更像是在给“任务额度”定价。68 元不是买一个聊天框，而是买复杂工作场景的使用额度；200 元、500 元的差异，也主要对应更高的额度。

这对中文用户很关键。因为大多数人不是缺一个能聊天的 AI，而是缺一个能把表格整理完、把会议纪要归档、把页面做出来、把流程自动执行掉的工具。

如果 AI 只是回答，用户会拿它和搜索、资料库、免费模型比较。可一旦 AI 能连续操作工具，用户比较的对象就变了：外包、实习生、自动化脚本、SaaS 插件，甚至自己半天的工作时间。

## Notion 的选择，给开发者一个提醒

Notion 没有自己从零建设编码智能体，而是把 Cursor SDK 接进产品。Cursor 官方文章里提到，Notion 的讨论串对应一个 Cursor agent，每条消息对应一次 agent run，结果通过 SSE 流式返回；Cursor SDK 提供模型、运行时、远程 MCP、云沙箱和工具调用能力。

这个选择值得创业团队认真看。

很多团队一听到 Agent，就想自己做一整套：任务编排、代码执行、浏览器操作、权限、安全、日志、失败恢复、PR 创建。真正做起来会发现，这些都不是漂亮 Demo 里的边角料，而是产品能不能给企业用的主结构。

Notion 的做法是把自己擅长的地方留住：文档、讨论、数据库、团队上下文。把高度专业的 agent infrastructure 交给 Cursor。它卖给用户的不是“我也有一个 AI 编程助手”，而是“你在 Notion 里的工作可以直接变成 PR”。

对开发者和产品经理来说，这个信号很现实：未来的 AI 产品未必都要自建智能体底座。更可行的路线，是找到高频工作场景，把上下文、权限、协作界面做好，再接入成熟的 agent runtime。

## Gemini 的 Computer Use，把门槛继续往下推

Google 把 Computer Use 做进 Gemini 3.5 Flash，也在降低开发门槛。开发者可以通过 Gemini API 和 Gemini Enterprise Agent Platform 使用这项能力，用来做持续软件测试、跨应用知识工作等长任务。

但 Google 同时强调了安全边界：敏感或不可逆操作需要用户确认；检测到间接提示注入时可以自动停止任务。这个部分不该被忽略。

Agent 能操作电脑之后，价值变大，风险也变大。一个能替你点按钮、读网页、写文件的系统，不能只靠“模型应该懂”来保证安全。权限、沙箱、用户确认、审计记录，会成为企业采购时真正关心的部分。

这也是为什么 Agent 产品的收费会更像生产力工具，而不是内容工具。它处理的不是一次问答，而是一段有目标、有权限、有成本、有风险的工作过程。

## 该怎么判断一个 Agent 产品值不值得做

接下来，很多团队会把“Agent”写进产品介绍里。但真正值得做的，不是加一个自动执行按钮，而是回答三个问题。

第一，它能不能接近真实工作流？用户平时在哪里交代任务，素材在哪里，结果要交到哪里，谁来确认，失败后怎么接着处理，这些比模型宣传词更重要。

第二，它能不能形成可理解的计费单位？如果用户不知道一次任务消耗什么、套餐差异在哪里、重度使用会不会失控，就很难持续付费。豆包把 68、200、500 元与不同额度绑定，本质上是在尝试把 Agent 成本产品化。

第三，它能不能把安全机制讲清楚？尤其是浏览器操作、本地文件、企业知识库、代码仓库这些场景，权限设计不是附加项。用户不是怕 AI 不聪明，而是怕它太能动，且动错地方。

## 这轮变化对中文 AI 创业者的启发

如果你正在做 AI 产品，不要只盯着模型榜单。更值得看的是这些问题：

- 哪个场景里，用户愿意为“少做一段真实工作”付费？
- 哪些上下文是你独有的，而通用模型公司拿不到？
- 哪些执行能力可以接入现成 SDK、MCP、浏览器自动化或云沙箱？
- 哪些操作必须让用户确认，哪些必须限制权限？

豆包专业版让普通用户第一次直观看到：会干活的 AI 可以有清晰价格。Notion 和 Cursor 说明：协作软件可以把任务变成代码交付。Gemini 说明：Computer Use 正在成为模型平台的基础能力。

所以今天最值得关注的不是“谁又出了一个更聪明的模型”，而是另一个问题：

当 AI 真的开始替人执行任务时，你的产品是在卖回答，还是在卖一段可验证的工作？
