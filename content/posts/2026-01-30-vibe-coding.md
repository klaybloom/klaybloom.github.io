# hexo-rs：玩 Vibe Coding

hexo-rs 是我拿来练手的一个小项目：目标不是重新发明一个完整博客系统，而是用 Rust 写一个足够清楚的静态内容管线，顺便观察 AI 编程在真实项目里的边界。

## 我给模型的任务边界

一开始我尝试把需求写得很大，结果模型会倾向于一次性生成很多抽象。后来我把任务拆成更窄的单位：

- 解析 Front Matter。
- 生成 slug。
- 按日期排序。
- 把 Markdown 渲染成 HTML。
- 输出一个最小可访问页面。

每个任务都能单独验证，返工成本就低很多。

## 一个有效的节奏

```ts
export const workflow = [
  "写一个很小的测试",
  "让模型补最短实现",
  "自己检查边界",
  "再让模型整理重复代码",
];
```

这类节奏不浪漫，但有效。模型适合生成候选实现和补齐机械代码，人还是要负责边界、命名、取舍和最终结构。

## 当前判断

Vibe Coding 对我最有价值的地方不是“少写代码”，而是让我更快得到一个可以批判的版本。只要测试足够小、反馈足够快，它会显著缩短探索时间。
